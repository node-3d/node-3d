# Three.js decoder worker experiment

The old palette sample at `packages/core/examples/core/palette/utils/` copied a
version of `DRACOLoader` and replaced its worker creation with Node worker
threads. That copy is now substantially older than the installed Three.js
`0.186.1` loader. The current npm package already contains the Draco JS/WASM
decoders and Basis JS/WASM transcoder under `examples/jsm/libs/`.

This research browser now imports the **unmodified** Three.js `DRACOLoader` and
`KTX2Loader`. The host supplies two shared facilities:

1. The default and example-created `LoadingManager` instances convert decoder `file:` URLs inside the installed
   Three.js `examples/jsm/libs/{draco,basis}` directories to data URLs. Node
   `fetch()` cannot read those `file:` URLs, while Three's `FileLoader` can read
   the resulting data URLs. Other example assets still use pinned upstream
   HTTP URLs.
2. A small `Worker` facade resolves the Blob URL generated by Three.js and
   starts a Node worker thread. The worker exposes `self`, `postMessage`,
   `onmessage`, and `addEventListener('message')`, then evaluates Three's
   generated decoder body. It also supplies the CommonJS globals expected by
   the bundled Draco WASM wrapper. Worker threads do not inherit Node3D's
   graphics preload.

The addon code and decoder binaries are not copied or patched. The bridge is
local to this research preload; it is not a general Web Worker implementation.

## Live checks

From `research/lil-gui`:

```powershell
node examples/decoder-probe.ts
node example-browser.ts probe webgl_tonemapping
```

On Windows x64 with Node 24.13.0 and Three.js 0.186.1, the first command
decoded 40×40 ETC1S and UASTC KTX2 textures, rendered the ETC1S texture with
nonuniform framebuffer pixels, and decoded 34,834 vertices from the upstream
Draco bunny. The second command rendered the unmodified upstream tonemapping
example, whose glTF uses Draco compression. Its 12-frame framebuffer probe
passed.

## Remaining limits

- The research `Worker` facade handles the message APIs used by these two
  loaders and Node Blob URLs generated in the same thread. It does not support
  arbitrary worker URLs, `importScripts`, or the full browser Worker lifecycle.
- KTX2's `detectSupport()` exposed a separate Node3D ASTC extension mismatch:
  `getSupportedProfiles()` returned `undefined` where Three.js expects an
  array. The preload normalizes this to `[]`. This is a candidate for a core
  WebGL compatibility fix if KTX2 support is promoted.
- Decoder `file:` remapping is deliberately scoped to bundled Three.js decoder
  libraries. Custom decoder paths and arbitrary local assets need explicit
  handling.
- The probes cover ETC1S, UASTC, one Draco geometry, and one compressed glTF
  scene. They do not establish every KTX2 GPU format, multiple concurrent
  workers, cancellation/disposal under load, other platforms, or full visual
  parity for the tonemapping page.

The practical path for this Three.js version is a shared host adapter. Keeping
the old full-loader copy would preserve a large amount of stale upstream code
without solving KTX2 or other worker-based addon families.
